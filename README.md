# RootBridge

RootBridge helps children, families and independent learners learn a heritage language and its culture.

- **Languages:** Nepali, Finnish, Japanese and Twi, each with a **language path** and a **culture path**.
- **Content:** 134 modules and 536 lessons.
- **Stack:** React 19 + Vite on the frontend, Express 4 + MongoDB (Mongoose) on the backend.
- **Security:** passwords hashed with **bcrypt**, logins with **JWT**.
- **Deployment:** one web service serves both the API and the website.

> Sprint 3 was built step by step on top of Sprint 2 (`SPRINT3_PLAN.md` has the plan and the reasons behind each decision). The git history has one commit per step.

## 1. Who can do what

| Account (role value) | What it gets |
| --- | --- |
| **Child/Parent** (`CombinedChildParent`) | **One login for a family.** It opens in the **child view**: lessons with unlimited tries and free hints, the Cultural Passport, classes. **Switch to Parent View** (optionally behind a 4-digit PIN) shows progress and parent controls. |
| **Normal** (`NormalUser`) | An independent learner. Same lessons, plus **7 hearts** (shown in the top bar on every page), fill-the-gap and word-order exercises, "Explain more" panels, and **strict pronunciation grading**. |
| **Teacher** (`Teacher`) | Creates classes with **6-digit join codes**, can **list a class publicly** so learners can find it, answers **requests to join**, adds a **live-class link** (Zoom, Teams, Meet), follows each student's progress, posts **homework**, and shares **files and links**. |

**How new accounts start:**

1. Sign up.
2. Learners pick a language in the **Language Hub**.
3. A short welcome animation plays.
4. You land on your own home page.

## 2. Run it on your computer

You need **Node.js 20+** and a **MongoDB** database. Either install MongoDB on your computer, or use a free **MongoDB Atlas** cluster (section 4, step 1).

### Backend (terminal 1)

```bash
cd backend
npm install
cp .env.example .env      # on Windows: copy .env.example .env
```

Open `backend/.env` and fill in at least these two:

```
MONGODB_URI=mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/rootbridge?retryWrites=true&w=majority
JWT_SECRET=<a long random string>
```

- **Mind the database name.** Put `/rootbridge` **before** the `?`. Without it, everything goes into a database called `test`.
- **Make a random secret with:** `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`

Then load the courses and start the server:

```bash
npm run seed              # loads all 4 languages + the demo accounts
npm run dev               # http://localhost:5000
```

### Frontend (terminal 2)

```bash
cd frontend
npm install
cp .env.example .env      # VITE_API_URL=http://localhost:5000/api
npm run dev               # http://localhost:5173
```

### Seed commands

| Command | What it does |
| --- | --- |
| `npm run seed` | **Replaces all course content** (so the database always matches the files) and adds any missing demo accounts. Existing users are kept. |
| `npm run seed:reset` | The same, but first **deletes every user**, and everything belonging to them: classes, homework, uploaded files, join requests, progress and messages. A true clean start. |
| `npm run seed -- --no-demo` | Skips the demo accounts. **Use this on a public site:** their password is written in the code. |

### Optional: the AI pronunciation coach

Put a free key from Google AI Studio (aistudio.google.com/apikey) in `GEMINI_API_KEY`. Without a key, a strict local check grades speaking instead, and lessons never break.

## 3. Tests

```bash
cd backend
npm test          # 74 tests
```

- **The backend tests use a real database,** a separate one called `rootbridge_test`, so your data is never touched. With a local MongoDB they just work. With Atlas, set `MONGODB_URI_TEST` to a test database first.
- **Without any database, the tests are skipped, not failed.** Run `npm run test:ci` to make a missing database a failure. GitHub Actions does this automatically (`.github/workflows/ci.yml`).
- **Postman:** import `postman/RootBridge.postman_collection.json`, run `npm run seed:reset`, start the backend, then run the collection top to bottom (the login requests save their tokens). It has 69 requests and 163 checks. The collection is generated by `postman/tools/build_collection.py`.
- **Browser tests:** `tests-e2e/` has one Playwright script per step (Steps 2–6: 197 checks). They need the backend on port 5000 and the built frontend on port 4173. See the top of each file.

## 4. Publish it on the internet (free: MongoDB Atlas + Render)

You get **one web address** that serves the website and the API.

### Step 1 — the database (MongoDB Atlas)

1. Create a free account at **mongodb.com/atlas** and create a **free (M0) cluster**.
2. **Database Access:** add a user with a password (avoid `@ : / ?` in the password, or it breaks the address).
3. **Network Access:** add `0.0.0.0/0`, so the hosting service can connect.
4. **Connect → Drivers:** copy the connection string, and add `/rootbridge` before the `?`:
   `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/rootbridge?retryWrites=true&w=majority`

### Step 2 — the app (Render)

1. Push this project to GitHub.
2. On **render.com**: **New → Blueprint**, and pick the repository. Render reads `render.yaml`, which runs `npm run build` and then `npm start`.
3. Fill in the values Render asks for:
   - `MONGODB_URI` — the Atlas string from step 1
   - `CLIENT_ORIGIN` — the address Render gives you, e.g. `https://rootbridge.onrender.com`
   - `GEMINI_API_KEY` — optional
   - `JWT_SECRET` is generated for you.
4. When the first deploy is live, open the service's **Shell** tab and run **one** of these:
   ```bash
   cd backend && node scripts/seed.js              # with the demo accounts (good for a presentation)
   cd backend && node scripts/seed.js --no-demo    # without them (a real public site)
   ```
5. Check `https://YOUR-ADDRESS/api/health`. It should say `"database":"connected"`.

**Good to know about the free plan:** the app sleeps after about 15 minutes without visitors, and the next visit takes 30–60 seconds to wake it. **Open the site a minute before a presentation.**

### Other ways to run it

- **Docker, everything on one computer:**
  ```bash
  docker compose up --build
  docker compose exec app node backend/scripts/seed.js
  ```
  Then open http://localhost:5000.
- **Any host that runs Docker:** use the `Dockerfile`, and set the same environment variables.

### Four ideas that explain most of the code

1. **One source of course content.** The files in `frontend/src/data/` are the curriculum. The website reads them, and `seed.js` loads **the same files** into MongoDB, so the two can never disagree.
2. **Progress: browser first, server synced.** Lessons save instantly in the browser, then sync to `PATCH /api/progress/me` in the background. On login the server copy is merged back in, so progress follows the learner to another device, and teachers can see it.
3. **Only the server changes hearts.** The browser can ask to lose one or earn one, but never set the number. Clearing the browser gives no free hearts.
4. **Class files live in MongoDB (GridFS), not on the server's disk.** Free hosting wipes the disk at every redeploy; the database keeps them. Only the class's teacher and members can download them.

### Hearts (Normal learners only)

The hearts sit in the top bar, so they are visible on the dashboard, the paths and inside a lesson, and every screen shows the same number.

| Event | Hearts |
| --- | --- |
| Start | 7 |
| Wrong answer | −1 |
| The **first** hint on a question (after "Use a hint?") | −1 — further hints on that same question are free |
| "Very close" in speaking, or "I said it out loud" | no change (the self-check is not graded) |
| Module quest finished | back to 7 |
| Every 4 hours while below 7 | +1 |
| At 0: a perfect review of **any lesson you already finished** | +1 (once per lesson per day) |

### Joining a class: two ways

1. **With a code.** The teacher shares the 6-digit code; the learner types it under **Classes**.
2. **Without a code (Find a class).** A teacher can tick "list this class", with a short description. Learners then see it under **Classes → Find a class**, send a **short message**, and the teacher **approves or declines** (with an optional reply). The join code is never shown in the directory — only approval puts a learner in the class.

Classes are **private by default**; nothing appears in the directory until a teacher chooses to list it.

### The parent view and its PIN

- The switch in the top bar moves between the child view and the parent view.
- **Setting a PIN is offered right in the parent view** ("Protect the parent view"), not hidden in a settings checkbox.
- Opening `/parent` directly (a bookmark, or a refresh in the child view) shows an **unlock screen** on that same page where the PIN can be typed, instead of bouncing back to the dashboard.
- The PIN is checked on the server and never sent to the browser.
- **Forgot the PIN?** appears wherever the PIN is asked. The parent types the **account password**, then sets a new PIN or removes it, so nobody is ever locked out of their own parent view.

### The exercises

Each module has four lessons, and every lesson has a **phase** that decides how it feels, so the four lessons never feel the same:

| Track | Phases | Mechanics used |
| --- | --- | --- |
| Language | Encounter → Notice → Retrieve → Use | listen-and-choose, read-and-choose, **pair up**, spelling check, **odd one out**, **letter scramble**, word match, typing, speaking |
| Culture | Encounter → Notice → Compare → Create | read-and-choose, listen-and-choose, **pair up**, **true or false**, **odd one out**, word match, typing, speaking |

Normal learners also get **fill the gap** and **word order** on the module's real phrases, in a different slot each lesson, plus an "Explain more" panel (the word-by-word breakdown only appears once the step is solved, so it never gives the answer away).

Words with a blank in them (`मेरो नाम ___ हो।`) are **spoken without the blank**, so the voice never reads "underscore underscore underscore"; the blank still shows on screen.

**Typing** accepts either the native script or the romanisation (`namaste` for नमस्ते), because most learners have no Devanagari, kana or ɛ/ɔ keyboard.

## 6. API summary

All answers have the shape `{ success: true, ... }` or `{ success: false, error }`. A 🔒 route needs the header `Authorization: Bearer <token>`.

| Area | Routes |
| --- | --- |
| Health | `GET /api/health` |
| Auth | `POST /api/auth/signup`, `POST /api/auth/login` (the role must match), `POST /api/auth/forgot-password`, 🔒 `GET /api/auth/me` |
| Users 🔒 | `POST /api/users/update`, `POST /api/users/verify-pin`, `POST /api/users/pin/reset` |
| Courses 🔒 | `GET /api/tracks?language=`, `GET /api/tracks/:id`, `GET /api/modules/:id`, `GET /api/lessons/:id` |
| Progress 🔒 | `GET` + `PATCH /api/progress/me`, `POST /api/progress/lives/lose`, `POST /api/progress/lives/earn` |
| Speaking 🔒 | `POST /api/pronunciation/grade` |
| Classes 🔒 (teacher) | `POST`/`GET /api/groups`, `GET`/`PATCH`/`DELETE /api/groups/:id`, `/members/:userId`, `/assignments`, `/materials` |
| Classes 🔒 (learner) | `POST /api/groups/join`, `POST /api/groups/leave`, `GET /api/groups/mine`, `GET /api/groups/directory`, `POST /api/groups/:id/requests`, `GET /api/groups/requests/mine` |
| Requests 🔒 (teacher) | `GET /api/groups/:id/requests`, `POST /api/groups/:id/requests/:rid/approve`, `POST /api/groups/:id/requests/:rid/decline` |
| Files 🔒 | `GET /api/materials/:id/file` (class members only) |
| Contact | `POST /api/contact` |

## 7. Security, in short

- **Progress cannot be faked.** The server only accepts lesson and module ids that really exist, at most 20 per request, and **works XP out itself** instead of believing the browser. Hearts have always been server-only. This matters because a teacher's roster shows these numbers.
- **`details.classes` is server-managed:** class membership can only change by joining or leaving a class, not by editing your own account.
- **Photos** must be real image data and under 300 KB.
- **Teacher sign-up can need a code** (`TEACHER_SIGNUP_CODE`), because teachers see their students' names and progress.
- **Passwords:** bcrypt hashes, never returned, never logged.
- **Login errors:** the same message for "no account" and "wrong password", so nobody can discover accounts.
- **The parent PIN:** hashed, checked on the server; the browser only learns *whether* a PIN is set.
- **Roles:** checked on **every** API route, not just hidden in the pages.
- **HTTP protection:**
  - **helmet** headers with a strict Content Security Policy (it allows Google Fonts and nothing unexpected)
  - **CORS** limited to `CLIENT_ORIGIN`, and applied to `/api` only, so a mistyped address can never stop the website's own files from loading. Requests from the app's own address always pass.
  - rate limits on login, speaking and the contact form
- **Live-class links:** must be `https://` (no `javascript:` links).
- **Uploads:** 10 MB maximum, safe file types only, stored in the database, and downloadable by the class only.
- **The server refuses to start** in production without a real `JWT_SECRET`.

## 8. Known limits (honest list)

- **Content review:** the Twi content has been reviewed by a speaker. The Finnish and Japanese content was written carefully and kept general, but a native speaker should still read it before a public launch.
- **Password reset emails are not sent yet.** "Forgot password" gives the same answer for every email, but no email service is connected. Adding one (e.g. Resend or Nodemailer) is the next step.
- **Speaking** needs a browser with speech recognition (Chrome or Edge). Twi has no browser voice or recognition, so its words are read in English and graded with the text check.
- **"I said it out loud"** (the no-microphone fallback) still counts as correct, so speaking never blocks progress, as the brief asked.
- **Login tokens** are kept in the browser's `localStorage`. An httpOnly cookie would be safer against injected scripts, and it is the next thing I would change; it was left as it is because the development setup runs the website and the API on two different addresses, where such a cookie needs HTTPS to work at all. In production both run on one address, and the strict Content Security Policy (no third-party scripts) is what keeps this acceptable meanwhile.
- **The contact form** can be read at `GET /api/contact/messages` with the `x-support-token` header, once `SUPPORT_TOKEN` is set in `.env`. Without that setting the route is switched off, and nobody can read the messages.
- **The free Render plan** sleeps when idle (see section 4).

### If something looks wrong while developing

- **`nodemon` reloads code, but not `.env`.** After changing `.env`, stop the server (Ctrl+C) and start it again.
- **Make sure only one backend is running.** An old one left on port 5000 will keep answering with old code, which looks exactly like "my fix did nothing".
